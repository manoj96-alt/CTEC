## Current authoritative language

The Invocation Request contains “Protocol Version, Correlation Identifier, Request Identifier, Session Identifier, Request Classification, Opaque Payload.” The payload “SHALL NOT contain capability sequence, business semantics, or canonical ontology modifications.”

## Proposed additive language

An admitted invocation may carry **Trusted Runtime Control Metadata** separately from the Opaque Payload. For the RFC-014 bounded MVP it contains:

1. immutable `AuthorityContext` conforming to CIM-001; and
2. runtime-owned timezone-aware UTC `admitted_at`.

Trusted Runtime Control Metadata is not business payload, canonical ontology, capability sequencing, or a business artifact. AuthorityContext contains verified authority claims and references but no credential secrets. Claims embedded in Opaque Payload are never authoritative.

The Engine Access Facade validates schema, trust source, request/correlation equality, expiry, and authorization reference before admission. EIC preserves the metadata unchanged when transferring ownership to EOM. Business payload remains opaque to EIC and EOM.

## Reason

Adapters need trusted authority and timing provenance without weakening opaque invocation or allowing caller payload claims to control authorization.

## Compatibility

Additive at architecture level but not wire-compatible with implementations that cannot accept a separate control context. Existing opaque payload semantics remain unchanged. An implementation CDD must version the invocation contract and authorize exact file changes.

## Governance actions

After approval: publish EIC-001 v1.3; reconcile PAD and EOM; approve the separate CDD-010 clarification; update Registry/dependencies/checksums/manifest; run protocol compatibility and release gates.

## Validation and rollback

Validate payload opacity, metadata immutability, expiry, correlation equality, secret exclusion, unauthorized-claim rejection, and protocol version negotiation. Rollback must reject the new contract version rather than move AuthorityContext into Opaque Payload.
