## Current authoritative language

“Governance Outcomes are Compliant, Non-Compliant, Exception Granted, and Requires Review.” Governance Attestation is outcome-neutral and “is not an independently persisted business artifact.” Exception Granted requires a valid GEM-001 Exception Authorization. Governance “never executes enterprise operations.”

## Proposed additive language

For the RFC-014 supplier-risk sourcing-recommendation slice, Governance Attestation maps to integration standing as follows:

| GRM outcome | Integration standing | Actionability |
|---|---|---|
| Compliant | `APPROVED` | Actionable only by an authorized downstream human or system. |
| Exception Granted | `CONDITIONALLY_APPROVED` | Non-actionable until every condition recorded by the referenced Exception Authorization is verified satisfied. |
| Requires Review | `PENDING_REVIEW` | Non-actionable. |
| Non-Compliant | `REJECTED` | Non-actionable; final integration recommendation is `NO_AUTOMATED_RECOMMENDATION`. |

`INDETERMINATE` is not a GRM outcome. It is an integration standing used only when the integration cannot obtain sufficient non-conflicting evidence to invoke or complete Governance Evaluation.

Conditional verification evidence must reference the Exception Authorization, identify every recorded condition, identify the authorized verifier and verification authority, record the verification result and timezone-aware UTC timestamp for each condition, and preserve evidence references. All conditions must be verified satisfied before `CONDITIONALLY_APPROVED` becomes actionable. Verification does not modify the immutable Governance Evaluation Record or Exception Authorization; it is evaluated externally as governed standing evidence.

Governance does not execute the recommendation. RFC-013 remains controlling: Governance Authority grants authorization; Governance evaluates documented authority evidence.

## Reason

The mapping makes actionability explicit without renaming GRM outcomes or treating execution state as business standing.

## Compatibility

Existing GRM outcomes and records remain unchanged. The integration-standing projection is additive and bounded. A new persistence model is not authorized; any durable verification-evidence artifact requires separate governance before implementation.
