# CDD-043 — Ontology Quality Intelligence — Governed Agentic Remediation (OQI5)

Version: 1.0 FROZEN
Status: FROZEN
Implementation state: NOT STARTED
Governing authorities: CDD-039/040/041/042 (FROZEN, OQI1-4 — read-only consumed, never modified),
CDD-036 (FROZEN, Gate S — governed human approval; its exact digest/TOCTOU/consumption *pattern*
is reused, its concrete `GateSApprovalRequest`/`gate_s_approval_requests` are never extended or
modified — Sec9), CDD-037 (FROZEN, Gate V — deterministic governed agent-resolution; its historical
scope is preserved exactly as written, never retroactively broadened — Sec8)

Mandatory template: CDD Template v2.2

**Publication note**: this document freezes the architecture resolved across OQI5-DR (discovery),
OQI5-DR-R1 (narrow real-agent-reasoning resolution), and explicit Product Owner approval of both,
per the compressed governed-delivery pattern `DR → G → I1 → I2 → VM` established for OQI4 and
extended here with a genuine two-phase implementation split.

## 1. Purpose

Prove that CTEC can move from a governed Quality Finding to a governed, evidence-supported
remediation candidate, optionally enriched by real model-backed advisory investigation, to an
exact human-authorized remediation instruction, to externally/manually performed remediation, to
deterministic OQI re-evaluation against fresh immutable evidence — without ever allowing
nondeterministic model output, source majority agreement, or source authority metadata to become
enterprise fact, and without CTEC itself writing back to any source system.

## 2. Capability claim (exact, binding)

CTEC can, for an OPEN OQI1/OQI2/OQI3 Finding: deterministically extract evidence-supported
remediation candidate(s) (or none) from existing immutable OQI evidence; optionally invoke governed
real model-backed specialist and synthesizer agent reasoning that can only ever reference — never
invent — those candidates and their supporting/conflicting evidence; deterministically validate all
model output before any of it is treated as advisory; deterministically construct an exact
remediation instruction payload from the referenced candidate (never from model-generated text);
require independent human authorization, cryptographically bound to that exact payload and to the
Finding's exact state revision, before the instruction is considered authorized; record external or
manual performance of that instruction as an unverified claim; and resolve the underlying Finding
only through the existing, unmodified OQI1-4 deterministic re-evaluation path against fresh
immutable evidence.

No broader claim (real source write-back, autonomous remediation, business criticality, monetary
impact, explainable trust, agent-to-agent free-form conversation, tool-calling agents, frontend, or
Gate V/Gate S file modification) is authorized by this CDD.

## 3. Why this CDD requires its own governance

OQI1-4 establish deterministic quality/impact facts but no remediation pathway. Gate S establishes a
governed human-authorization *pattern* but its concrete domain model is closed to a second action
type by its own frozen text (CDD-036 Sec14, Sec37, Sec38). Gate V establishes a deterministic,
non-AI agent-resolution *pattern* but explicitly contains no real LLM reasoning (CDD-037 Sec6).
Nothing in the repository combines governed multi-source evidence, real model-backed advisory
reasoning, exact human authorization, and deterministic re-evaluation into one safe pipeline. This
CDD is the first to do so.

## 4. Definitions

- **Remediation Case**: one stable, per-Finding aggregate persisting the deterministic remediation
  lifecycle across reopens, analogous to how one stable `BusinessRuleFinding` persists across its
  own reopen cycle.
- **Remediation Candidate**: an immutable, deterministically-extracted possible corrective value or
  action, computed by plain domain code reading existing OQI1/2/3 persisted evidence — never
  generated by a model.
- **Evidence-Supported**: a candidate's provenance traces to specific, real, persisted evidence IDs;
  a candidate with zero supporting evidence cannot exist.
- **Remediation Authorization**: OQI5's own governed human-approval record, modeled on — but
  structurally independent from — Gate S's `GateSApprovalRequest`, binding an exact deterministic
  action payload digest, requiring a human decision distinct from the requester.
- **Agent Role**: a versioned, governed definition of what a real model-backed reasoning component
  is permitted to reason about and recommend (OQI5-I2 only).
- **Agent Run**: an immutable record of one real model invocation, its governed evidence-packet
  digest, and its raw (schema-checked) or rejected structured output (OQI5-I2 only).
- **Agent Recommendation**: validated, advisory-only structured model output that may *reference* a
  Remediation Candidate by ID; it never carries an independently authoritative proposed value
  (OQI5-I2 only).
- **Remediation Instruction**: the deterministically-constructed exact payload (never model-derived
  text) submitted for Remediation Authorization.
- **External Remediation Claim**: a human-reported statement that an authorized instruction was
  performed outside CTEC; a claim, never proof, of quality resolution.

## 5. In scope

**OQI5-I1 — Deterministic Remediation Foundation**: `RemediationCase`, deterministic
`RemediationCandidate` extraction from OQI1/OQI2/OQI3 evidence (N-source generic, dissent- and
missingness-preserving), `RemediationInstruction` construction, OQI5's own governed
`RemediationAuthorization` (modeled on Gate S's exact digest/TOCTOU/consumption pattern),
manual/external remediation-claim recording, and linkage to the existing, unmodified OQI1-4
re-evaluation entrypoints. Fully useful and shippable with zero AI.

**OQI5-I2 — Governed Real Agent Reasoning** (separately authorized, gated behind OQI5-I1's own
closure): a narrow OQI5-local `ModelProvider` interface + one initial adapter; versioned
`AgentRole`; immutable `AgentRun`; deterministic `AgentEvidencePacket` construction from OQI1-4
facts and I1's candidates; the M2 topology (two parallel specialist `AgentRun`s + deterministic
code-only aggregation + one Recommendation Synthesizer `AgentRun`); a deterministic
`AgentRecommendationValidator`; immutable, validated `AgentRecommendation`; composition into I1's
existing `RemediationInstruction` construction as optional provenance metadata only.

## 6. Out of scope (binding)

Any modification to any file governed by CDD-036 (Gate S) or CDD-037 (Gate V), or to either CDD
document itself. Any modification to OQI1 (`app/domain/oqi/`), OQI2 (`app/domain/oqi_cross_source/`),
OQI3 (`app/domain/oqi_business_rule/`), or OQI4 (`app/domain/oqi_ontology_impact/`) domain,
persistence, or application files. Real source-system write-back of any kind. Autonomous
remediation. Direct agent tool calls (zero in v1). Agent-to-agent free-form conversation. A
generalized multi-provider or multi-tenant-of-capability AI platform. Business criticality,
monetary impact, or trust-score computation (OQI6). Any dashboard/frontend/graph UX (OQI7). Any API
endpoint (deferred; a future, separately-authorized phase). Chain-of-thought persistence. Rule,
ontology, or source-authority modification via remediation.

## 8. Primary invariants (binding, frozen)

1. Model output is not fact. 2. Agent assessment is not fact. 3. Agent recommendation is not truth.
4. Agent consensus is not truth. 5. Majority source agreement is not truth. 6. Source authority is
not truth. 7. Deterministic candidates precede any consequential recommendation. 8. Unsupported
values cannot become consequential action payloads. 9. All model references must bind to real,
governed input facts or be rejected. 10. Dissenting/conflicting evidence must never be silently
omitted from a recommendation. 11. OQI4 `IMPACT_UNKNOWN` remains `IMPACT_UNKNOWN`, never upgraded.
12. Recommendation is not authorization. 13. Human authorization binds to an exact, deterministically
constructed action payload. 14. A changed Finding revision, candidate set, or payload invalidates a
prior authorization (fail closed). 15. No agent code holds source-write credentials or a
source-write path. 16. No agent code can create, approve, or execute a Remediation Authorization on
its own behalf. 17. Provider failure never affects deterministic OQI truth. 18. The deterministic
remediation path (I1) functions correctly with zero AI availability. 19. An external execution claim
is never quality resolution. 20. Only fresh immutable evidence plus deterministic OQI re-evaluation
may resolve a Finding. 21. Historical `AgentRun`/`AgentRecommendation`/`RemediationAuthorization`
records are never rewritten. 22. Tenant boundary holds across every referenced entity in the entire
chain. 23. Chain-of-thought is neither required nor persisted.

## 9. Gate S composition boundary (binding, load-bearing)

CDD-036 Sec14 freezes `gate-s-governed-note-write` as the only registrable action and Sec37/Sec38
explicitly reserve any second action type for "its own, separate, explicit Product Owner
architecture decision" that CDD-036 does not pre-authorize. `GateSApprovalRequest.__post_init__`
(domain/gate_s/approval.py) enforces this in code: it raises `ValidationException` for any
`action_id != "gate-s-governed-note-write"`. **This CDD is that separate, explicit Product Owner
architecture decision — for OQI5's own action, not a modification of Gate S's.** OQI5 therefore
introduces its own domain object, `RemediationAuthorization`, and its own table,
`oqi_remediation_authorizations` — structurally independent from `GateSApprovalRequest`/
`gate_s_approval_requests` — reusing verbatim the *pattern* CDD-036 Sec16-Sec18 established:
canonical-JSON SHA-256 digest computed at request time over the exact deterministic payload,
recomputed and compared at execute time (TOCTOU protection, fail-closed on mismatch), row-locked
one-time consumption, self-approval prohibition, tenant isolation. `GateSApprovalRequest`,
`gate_s_approval_requests`, `gate_s_governed_notes`, CDD-036, and its Artifact Authorization remain
byte-unchanged and unimported by any OQI5 file except for documentation/precedent reference.

## 10. Gate V composition boundary (binding, restated)

CDD-037 Sec6 states Gate V v1 contains no real LLM/AI reasoning and exactly one named
non-AI agent. This CDD does not modify that claim. **OQI5 introduces CTEC's first real
model-backed advisory reasoning capability; Gate V never had one and this document does not
retroactively assert otherwise.** `backend/app/domain/gate_v/agent_resolution.py`,
`gate_v_agent_service.py`, CDD-037, and its Artifact Authorization remain byte-unchanged.

## 11. Remediation Case (I1, binding)

One `RemediationCase` per stable Finding identity (`tenant_id + finding_family + finding_id`),
created on first candidate extraction, reused (not re-created) across Finding reopens. Fields:
`case_id` (deterministic from Finding identity, mirroring `derive_business_rule_finding_id`'s
pattern), `tenant_id`, `finding_family` (`OQI1`|`OQI2`|`OQI3`, closed), `finding_id`, `status`
(`CANDIDATE_READY`|`AWAITING_AUTHORITY`|`AUTHORIZED`|`EXTERNAL_EXECUTION_REPORTED`|
`AWAITING_REEVALUATION`|`RESOLVED`|`STEWARD_INVESTIGATION`|`NO_REMEDIATION`, longest value
`EXTERNAL_EXECUTION_REPORTED` = 25 chars, column `String(32)`, verified safe), `created_on`,
`updated_on`.

## 12. Remediation Candidate (I1, binding)

Immutable, one row per deterministically-extracted candidate per case per extraction pass. Fields:
`candidate_id` (deterministic digest of case + target + proposed value + supporting evidence set,
role-sorted), `case_id`, `target_source_object_id`, `target_source_field_id`, `proposed_value`,
`supporting_evidence_ids[]`, `conflicting_evidence_ids[]`, `missing_participant_roles[]`,
`authority_participant_role` (nullable, metadata only, never a correctness claim), `basis`
(`OQI1_COMPLETENESS`|`OQI1_VALIDITY`|`OQI2_CONSISTENCY`|`OQI3_BUSINESS_RULE`, closed, longest
value `OQI2_CONSISTENCY` = 16 chars, `String(32)` safe), `extracted_at`. Zero deterministic
candidates is a valid, expected outcome (Case moves to `STEWARD_INVESTIGATION`); the engine never
fabricates a value absent supporting evidence.

## 13. Remediation Instruction (I1, binding)

Immutable. Fields: `instruction_id`, `case_id`, `candidate_id` (FK), `finding_state_revision` (the
exact Finding revision seen at construction time), `action_type` (`UPDATE_FIELD`, closed — the only
v1 action type; `CREATE`/`DELETE`/multi-field actions explicitly excluded per OQI5-DR §136-138),
`agent_recommendation_id` (nullable, I2-only, provenance metadata never a payload input),
`payload_digest` (SHA-256 canonical JSON over `{tenant_id, finding_id, finding_state_revision,
case_id, candidate_id, target_source_object_id, target_source_field_id, action_type}` — deliberately
excludes `proposed_value` as a separate field since it is already implied by `candidate_id`,
preventing any drift between the candidate's real value and the authorized payload), `created_by`,
`created_on`.

## 14. Remediation Authorization (I1, binding — the OQI5-owned Gate-S-pattern object)

Fields mirror `GateSApprovalRequest` exactly in shape: `authorization_id`, `tenant_id`,
`instruction_id` (FK, not `action_id`/`note_text` — OQI5's payload identity is the instruction, not
a free string), `payload_digest` (copied from the instruction at request time, immutable),
`requested_by`, `requested_on`, `status` (`PENDING`|`APPROVED`|`REJECTED`, closed, three states
only, mirroring CDD-036 Sec15 exactly), `decided_by`, `decided_on`, `rejection_reason`,
`consumed_on`, `consumed_execution_id`. At authorization-execute time, the instruction's payload
digest is recomputed from the instruction's current referenced facts (re-reading the candidate and
Finding's current `state_revision`) and compared to the stored digest; any mismatch fails closed
with `REMEDIATION_ACTION_MISMATCH` and zero state change — the direct OQI5 analogue of
`APPROVAL_ACTION_MISMATCH`. Self-approval prohibited (`REMEDIATION_SELF_APPROVAL_PROHIBITED`).
Tenant mismatch fails closed (`REMEDIATION_TENANT_MISMATCH`). One-time consumption enforced inside
the same row-locked transaction, exactly as CDD-036 Sec18/Sec20.

## 15. Staleness contract (binding)

Because `payload_digest` includes `finding_state_revision`, any of the following before execution
produces a digest mismatch and fails closed with zero new machinery: the Finding transitioned to a
new revision (repeated violation, resolution, reopen); the candidate set changed (re-extraction
produced different candidates); the underlying OQI4 impact evaluation changed, if it participated in
candidate selection. No separate staleness table, expiry clock, or polling mechanism is introduced.

## 16. Manual/external execution (binding, E2)

`RemediationAuthorization` consumption transitions the `RemediationCase` to
`EXTERNAL_EXECUTION_REPORTED` upon an explicit, separately-authenticated human report — this report
is persisted as an `External Remediation Claim` (a boolean-plus-timestamp field on the case,
carrying no independent truth weight) and never itself changes `status` to `RESOLVED`. No source
connector, credential, or write path is introduced. CTEC performs no source mutation.

## 17. Re-evaluation composition (binding)

OQI5 introduces zero new evaluation logic. Resolution of the underlying Finding occurs exclusively
through the pre-existing, unmodified `evaluate_current_state` entrypoints of OQI1/OQI2/OQI3, and the
pre-existing, unmodified `evaluate` entrypoint of OQI4, triggered by ordinary fresh-evidence
ingestion. `RemediationCase.status` transitions to `RESOLVED` only as a read-only reflection of the
Finding's own resolved state at the next case-status refresh — it never asserts resolution
independently.

## 18. OQI5-I2 — AgentRole, AgentRun (binding)

`AgentRole`: versioned (`role_id`, `version`, `ACTIVE`|`RETIRED`), governed instruction text stored
with the version (never embedded as a mutable code string), closed
`allowed_recommendation_types[]`. `AgentRun`: immutable, `run_id` (generated, not deduplicating —
retries may legitimately differ), `role_id`+`role_version`, `provider`, `model`,
`evidence_packet_digest` (deterministic, order-independent — canonical hash over
`{finding_id, finding_state_revision, evaluation_id, sorted(candidate_ids), sorted(evidence_ids),
impact_evaluation_id, role_version, schema_version}`), `raw_output` (stored only if it parses as
well-formed JSON; malformed non-JSON output is recorded only as a failure classification, never
stored raw), `result_state` (`SUCCEEDED`|`FAILED`|`REJECTED_OUTPUT`, closed), `created_on`. No
chain-of-thought field exists in this schema.

## 19. OQI5-I2 — AgentEvidencePacket (binding)

Deterministically constructed by I1-owned code from existing persisted facts only — never a live
query the model can wander through. Represents 2..N participants generically (role, source-system
role, observed value or explicit `MISSING`, evidence_id, conflict flag, authority flag as metadata
only). Carries OQI4 impact as its literal enum value, including `IMPACT_UNKNOWN` verbatim. Every
referenced fact carries a stable ID the deterministic validator can check.

## 20. OQI5-I2 — M2 multi-agent topology (binding, frozen)

Exactly two parallel specialist `AgentRun`s against the identical evidence packet: **Evidence &
Consistency Analyst** (OQI1/2/3 facts, candidates, agreement/conflict) and **Impact & Continuity
Analyst** (OQI4 impact/path evidence, Finding lifecycle history). Each specialist output passes
through the deterministic validator independently. Aggregation is plain deterministic code (union of
cited references, concatenation of structured assessments) — never a third model call — so
aggregation itself introduces no new hallucination surface. One **Recommendation Synthesizer**
`AgentRun` consumes only the validated aggregate (never raw specialist text), producing the final
structured recommendation, which passes through the identical validator again. No dynamic
orchestrator, no sequential-only chain, no source-specific or function-specific agent classes (role
specialization is evidence-packet content, not code).

## 21. OQI5-I2 — Deterministic validation contract (binding, load-bearing)

`AgentRecommendationValidator` (plain code, not a model call) rejects — never coerces or
silently repairs — any output that: references a `candidate_id` not present in the evidence packet;
references an `evidence_id`/`impact_id` not present in the evidence packet; specifies a
`recommendation_type` outside the invoking `AgentRole`'s closed `allowed_recommendation_types`;
references any tenant-inconsistent identifier; carries a `conflicting_evidence_ids` output that is a
strict subset of the candidate's own known conflicting-evidence set (dissent-omission detection —
the validator, not the model, is authoritative on what dissent exists); or attempts to supply an
independent `proposed_value` for a consequential recommendation (only `candidate_id` reference is
accepted; the actual value is read from the already-persisted candidate, never from model text).
Closed recommendation-type vocabulary: `RECOMMEND_CANDIDATE`, `REQUEST_STEWARD_INVESTIGATION`,
`NO_REMEDIATION_RECOMMENDED` (longest value 26 chars, `String(32)` safe).

## 22. OQI5-I2 — AgentRecommendation (binding)

Immutable, created only after successful validation. Fields: `recommendation_id`, `run_id` (FK),
`case_id`, `recommendation_type`, `candidate_id` (nullable — absent for
`REQUEST_STEWARD_INVESTIGATION`/`NO_REMEDIATION_RECOMMENDED`), `supporting_evidence_ids[]`,
`conflicting_evidence_ids[]`, `rationale` (bounded string, schema-constrained to reference IDs/facts,
not free chain-of-thought), `created_on`. Composition into I1: `RemediationInstruction.
agent_recommendation_id` may reference this row as provenance metadata; the instruction's
`payload_digest` never includes any `AgentRecommendation` field.

## 23. Provider architecture (binding)

A narrow `ModelProvider` interface, owned by OQI5 alone (not a generic CTEC runtime, not a Gate V
extension — no second consumer exists to justify a shared platform), with responsibilities limited
to: provider/model identity, structured-output invocation, timeout, typed error classification. One
initial concrete adapter behind it. Credentials are owned by the adapter's configuration layer only
— never persisted in `AgentRun`, never logged, never included in the evidence packet. Provider
unavailability degrades I2 gracefully; I1's deterministic path requires zero provider availability
(Invariant 18).

## 24. Security firewalls (binding)

Zero direct agent tool calls in v1 — the single strongest injection mitigation, since a model with
no callable tool has no injection payoff beyond producing text, which is fully re-validated against
closed IDs/enums before anything persists. Source-derived values occupy a structurally separate
field from governed instruction text in the evidence packet; instruction text is versioned per
`AgentRole` and never contains source-derived content. No agent-to-agent free-form messaging. No
cross-tenant context batching. Every persisted OQI5 entity carries `tenant_id`.

## 25. Test obligations (minimum set, both phases)

**I1**: candidate extraction from OQI1/OQI2/OQI3 fixtures (including dissent/missingness
preservation, N=5 participant scenario); zero-candidate → `STEWARD_INVESTIGATION`; instruction
payload-digest construction and recomputation; `RemediationAuthorization` full lifecycle (request,
decide, self-approval denial, cross-tenant denial, digest-mismatch fail-closed, one-time-consumption,
concurrent-decide/execute races on real Postgres); Finding-revision-changes-before-execution
staleness test (real Postgres); case reopen reusing stable case identity; re-evaluation linkage
proof (execution report does not itself resolve Finding).
**I2**: evidence-packet determinism/digest-order-invariance; specialist parallel execution;
validator rejection tests for every category in Sec21 (unknown candidate/evidence/impact,
disallowed type, cross-tenant, dissent-omission, unsupported value injection); aggregation
preserves disagreement (specialists disagree → both surface); consensus-does-not-equal-truth test;
provider-timeout/malformed-output/retry tests using a deterministic fake `ModelProvider` (no live
network dependency in normal CI); prompt-injection adversarial test (malicious source value cannot
escape the structured data field or authorize anything); all five OQI5-DR/DR-R1 crown scenarios
(N-source agreement, conflict, authority-conflict, business-rule no-candidate, OQI4
`IMPACT_UNKNOWN`).
