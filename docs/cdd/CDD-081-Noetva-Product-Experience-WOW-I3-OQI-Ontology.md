## 11. Evidence Rail — frozen design

**Purpose:** show what each real, governed source says about the same enterprise fact, without declaring a winner unless real authority data says so.

**Data contract:** `GET /findings/{id}/evidence` (unchanged) → `{participants: EvidenceParticipant[], candidate: EvidenceCandidate|null}`, `EvidenceParticipant = {source_system, observed_value, is_missing, is_authoritative, is_conflicting}`.

**Visual grammar:** one compact card/row per participant — `source_system` as the label, `observed_value` as the primary text. `is_conflicting=true` → `StatusIndicator status="conflict"`. `is_missing=true` → `StatusIndicator status="unknown"` with explicit text "Not reported" (never a blank cell). `is_authoritative=true` → a small plain-text "Authoritative" label (not a `StatusIndicator` state — authority here is a property, not a settled/unsettled state; misusing the vocabulary for it would blur the two concepts). No confidence score, no consensus value, no invented source.

**Empty state (family-aware, zero new backend field):** when `participants` is empty, the finding's own already-fetched `finding_family` (real, no extra call) determines the copy — `finding_family !== "OQI2"` → truthful "This finding type does not compare multiple sources" (Classification D, §5), never a bare "No evidence" that would wrongly imply evidence is missing when the concept doesn't apply. `finding_family === "OQI2"` with a genuinely empty result → the existing `EmptyState kind="empty"` truthful-empty pattern.

**States:** `loading`/`not-authorized`/`error` reuse the existing `EmptyState` kinds exactly as Overview already established; no new kind required.

**Truth constraints:** never a fabricated third source; never infer a "winner" from `is_conflicting` alone; `candidate` (a separate, family-independent field) is rendered only if the API returns it, never synthesized.

## 15. Governed lifecycle representation

The conceptual `Detect → Evidence → Assess → Recommend → Authorize → Remediate → Re-evaluate → Resolve` sequence maps directly onto real, already-observable backend state — no new state machine is introduced: Detect/Evidence/Assess are proven by the finding's existence plus its Evidence/Ontology-Impact data (already real); Recommend = `AgentRecommendationRow` present or null; Authorize = `RemediationAuthorizationRow.status`; Remediate = `RemediationExternalExecutionRow` presence; Re-evaluate/Resolve = the real `AWAITING_REEVALUATION`/`RESOLVED` stepper states (§13). This is architecture/storytelling language for how the Governed Decision Gate visually groups real states — it is never rendered as a second, competing lifecycle vocabulary alongside the product mental model (CDD-079 §2, not reopened) or as a progress bar implying completion of stages that are truthfully `NOT_INVOKED`/`NOT_EXERCISED`/`NOT_APPLICABLE`.
