# CDD Records

CDD implementation and review records belong here when supplied as versioned project artifacts. These files are audit and implementation records, not architecture authorities.

- `HISTORICAL — IMPLEMENTED` identifies completed CDD implementation records retained for traceability.
- `HISTORICAL — RESOLVED` identifies Architecture Clarification Reports closed by later governing artifacts.
- `HISTORICAL — SUPERSEDED` identifies work orders replaced by a later approved revision.

Historical CDD records are excluded from current architecture blocker checks. Current authority, document version, and baseline membership are determined only by `architecture/INDEX.md` and the applicable Architecture Release Manifest.

CDD Template v2.2 is mandatory for every new or revised CDD. CDD Template v2.1 is Superseded and non-compliant; it cannot authorize approval or implementation. Every CDD must include all five exhaustive authorization categories and must state `None authorized.` for an empty category.
