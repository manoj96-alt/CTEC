# Gate F — Proposed v1.11 Release Manifest Plan

Status: RELEASE CANDIDATE PLANNING ARTIFACT — NON-AUTHORITATIVE — NOT RELEASED

This is a planning document only. The actual `RELEASE-MANIFEST-v1.11.xlsx`
(checksummed, generated by `tools/generate_release_manifest.py` per the
`v1.8`/`v1.9`/`v1.10` precedent) is produced only at publication time, not by
F3. This Markdown plan identifies what that manifest will need to contain.

## Basis for this plan

`architecture/released/v1.10/` (the current baseline, PAD-002/Gate E — a
PAD-only release) is the closer structural precedent for Gate F than
`v1.8`/`v1.9` (RFC-driven, physical-model-regenerating releases), because
neither RFC-017 (taxonomy data rows only) nor CDD-015's persistence extension
(non-canonical, outside the Physical Model/EAD-001 boundary — see
`GATE-F-ARCHITECTURE-CONSISTENCY-REPORT_RELEASE_CANDIDATE.md` and RFC-017 §5)
triggers a Physical Model or EAD-001 regeneration. `v1.10/`'s actual contents
(`README.md`, `DEPENDENCY-MATRIX-v1.10.csv`, `PAD-002-..._FROZEN.md`,
`RELEASE-MANIFEST-v1.10.xlsx`, `ARCHITECTURE-CONSISTENCY-REPORT-v1.11_FROZEN.md`)
are the direct template.

## Versioning note (important, non-blocking — see F3 report §Part 10 finding)

`architecture/INDEX.md` documents that **document versions and
architecture-baseline versions are independent** (`architecture/INDEX.md:26`).
The "Architecture Consistency Report" document type is numbered on its own,
separate sequence that currently runs one number ahead of the baseline it
documents: `ARCHITECTURE-CONSISTENCY-REPORT-v1.11_FROZEN.md`
(`architecture/released/v1.10/`) is the consistency report **for the v1.10
baseline**, not a claim on baseline "v1.11". If Gate F's release becomes
baseline **v1.11**, its own Architecture Consistency Report would, by this
same established pattern, be versioned **v1.12** — this is expected, not an
error, and should not be mistaken for a second collision.

## What is explicitly NOT part of this plan

No new `ECOM_Physical_Data_Model_v1_8.sql`, no new `EAD-001-v1.8.json`, no
Logical Model edit — all three are carried forward unchanged, per the direct
evidence in RFC-017 §5 and the consistency report. This is a deliberate,
evidenced omission, not an oversight.
